# XLSX

Create new workbooks with XlsxWriter, analyze inputs without modifying them, and continue generated workbooks by patching their durable Python source and rebuilding. Never hand-author workbook XML for creation, install packages at runtime, or use openpyxl to save an uploaded workbook.

## Host Paths

- `<skills-root>` is the host-provided directory containing every installed skill. This skill is at `<skills-root>/xlsx`.
- `<project-root>` is the host-provided writable directory for the active document project.
- Editable source belongs under `<project-root>/src`; final artifacts belong under `<project-root>/out`.

These are host-provided values, not literal paths. Do not infer them from the shell's current directory. A host may expose the shared skills root as `AGENT_SKILLS_ROOT`; copied generators also accept `--skills-root`.

## Route The Request

| Request | Route | Read |
|---|---|---|
| Create a new `.xlsx` | XlsxWriter generator under `<project-root>/src` | `references/create.md`, `references/format.md`, `references/formulas.md` |
| Read or analyze `.xlsx`, `.xlsm`, `.csv`, `.tsv` | `scripts/read_workbook.py`, then pandas if needed | `references/read-analyze.md` |
| Continue a workbook generated by this skill | Read and patch its generator source, then rebuild | `references/continuation.md` |
| Validate and deliver | Build final recalculated bytes, then call `docQa` | `references/validate.md` |
| Modify an arbitrary uploaded workbook | Do not binary-edit it in this version | Explain the limit; offer analysis or a newly generated replacement |

## Creation Contract

1. Copy `<skills-root>/xlsx/templates/generate_workbook.py` to `<project-root>/src/generate.py` and adapt it rather than starting from an empty file.
2. Keep all editable logic and source data under `<project-root>/src`; write only temporary/final artifacts under `<project-root>/out`.
3. Use formulas for every derived value. Hard-code only supplied facts, labels, and explicit assumptions.
4. Use XlsxWriter for sheets, formulas, formats, tables, validation, charts, print areas, and navigation.
5. Write the initial workbook to a temporary `.xlsx`, then call `scripts/recalculate_workbook.py` from the generator to produce the final `.xlsx` with refreshed caches.
6. Write a sibling `<artifact>.qa.json` contract with exact sheets, important formulas, expected cells when known, chart requirements, and print settings.
7. Require successful generator exit and a non-empty final artifact, then call `docQa` exactly as the document-agent instructions require.

## Workbook Quality

- Separate assumptions, calculations, and executive outputs when the model has derived values.
- Make inputs visually distinct without relying on color alone; add labels or an input legend.
- Use explicit number formats for currency, percentages, dates, years, counts, and decimals.
- Set useful column widths, row heights, frozen panes, filters, and data validation.
- Keep gridlines and column structure visible on raw and cleaned data sheets unless the user explicitly requests a presentation-only view. Do not cover a data grid with a blanket white fill; freeze headers and identifier columns so records remain understandable while scrolling.
- Give charts descriptive titles, readable labels, and a secondary axis when series differ materially in scale.
- Set print areas, orientation, repeating rows, margins, and fit-to-width so rendered QA pages remain coherent.
- At five or more worksheets, put a linked `Index`, `Overview`, or `Navigation` sheet first.

## Formula Rules

- XlsxWriter formulas include the leading `=`.
- Formula cells remain formulas in the delivered workbook; never replace them with Python-computed values.
- Use absolute and mixed references deliberately and quote sheet names containing spaces.
- Guard expected zero denominators with an appropriate formula such as `IF` or `IFERROR` when the business meaning permits it.
- Treat a missing/stale cached result as a build failure, not as zero.
- If supplied assumptions contradict a supplied expected result, stop and report the contradiction. Never place an expected value elsewhere merely to satisfy QA.

## Reading Rules

- Reading is non-mutating. Do not call `save()` on an uploaded workbook.
- Use `data_only=False` to inspect formulas and `data_only=True` to inspect stored cached results.
- Never report an empty formula cache as a numeric zero.
- Base aggregations directly on source columns and report data-quality caveats.

## Continuation Rules

- Read the existing generator before editing it.
- Patch the smallest owning source region and rebuild; do not patch the generated `.xlsx`.
- Preserve sheet names, formulas, styles, chart series, and QA assertions not involved in the requested change.
- Recalculate, call `docQa` with changed scope when appropriate, and deliver a new revision only after it passes.

## Validation Boundary

`docQa` owns `scripts/validate_workbook.py`, LibreOffice rendering, visual inspection, bounded repair attempts, and SHA-256 evidence. The generator may call `scripts/recalculate_workbook.py` because recalculation creates the requested final bytes. Do not invoke the validator or visual QA commands through workspace shell tools.

## Runtime Contract

The required packages and binaries are listed in the repository-root `DEPENDENCIES.md` and `registry/dependencies.json`. They must be preinstalled before the agent starts; runtime installs and replacement skill downloads are forbidden.
